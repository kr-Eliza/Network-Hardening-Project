# 30-60-90 Day Plan - Consolidation and Production Rollout

## D+30 - Fix the critical risks (R-01, R-02, R-03)

### TLS certificate (R-01)

- [ ] Replace the self-signed certificate with a Let's Encrypt certificate using `certbot`
  ```bash
  apt install certbot python3-certbot-nginx
  certbot --nginx -d td4.example.com
  ```
- [ ] Configure automatic renewal with cron or a systemd timer
  ```bash
  systemctl enable certbot.timer
  ```
- [ ] Raise HSTS `max-age` to 31536000 in nginx_final.conf
- [ ] Add `ssl_stapling on;` and `ssl_stapling_verify on;` once the CA certificate is valid

### IPsec PKI (R-02)

- [ ] Create a dedicated strongSwan CA
  ```bash
  pki --gen --type rsa --size 4096 --outform pem > ca.key.pem
  pki --self --ca --lifetime 3650 --in ca.key.pem --type rsa \
      --dn "CN=VPN CA TD5" --outform pem > ca.cert.pem
  ```
- [ ] Issue one certificate per gateway (gw-fw, gw-fwB)
- [ ] Update ipsec.conf: `leftcert=gw-fw.cert.pem`, `rightcert=gw-fwB.cert.pem`
- [ ] Delete `/etc/ipsec.secrets` after a successful migration
- [ ] Document the revocation procedure (CRL)

### Suricata IPS (R-03)

- [ ] Test the switch to IPS mode in a staging environment
  ```bash
  iptables -I FORWARD -j NFQUEUE --queue-num 0
  suricata -c /etc/suricata/suricata.yaml -q 0
  ```
- [ ] Measure the performance impact (latency, throughput) with `iperf3`
- [ ] Define a blocking policy for high-confidence rules only
- [ ] Keep the local rules (SID 9000001-9000003) in `drop` mode instead of `alert`

## D+60 - Strengthen detection and observability (R-04, R-05, R-10)

### Log centralization (R-04)

- [ ] Deploy Elasticsearch + Kibana on a dedicated machine (or Docker container)
- [ ] Install Filebeat on `sensor-ids`, `srv-web`, `gw-fw`
  ```bash
  apt install filebeat
  filebeat modules enable suricata nginx system
  filebeat setup && systemctl start filebeat
  ```
- [ ] Configure Kibana dashboards for:
  - Suricata alerts by SID and by hour
  - Top source IPs generating alerts
  - nginx 4xx/5xx errors grouped by endpoint
  - Refused SSH connections (sshd log)
- [ ] Configure email/Slack alerts on the critical SIDs (9000001, 9000002, 9000003)

### SSH anti-brute-force (R-05)

- [ ] Install fail2ban on srv-web
  ```bash
  apt install fail2ban
  ```
- [ ] Configure `/etc/fail2ban/jail.d/sshd.conf`:
  ```ini
  [sshd]
  enabled  = true
  port     = 22
  filter   = sshd
  logpath  = /var/log/auth.log
  maxretry = 5
  findtime = 600
  bantime  = 3600
  ```
- [ ] Test banning and manual unbanning
- [ ] Also enable a jail for nginx (protection against scanning)

### IDS rules (R-10)

- [ ] Install `suricata-update` and enable ET-Open
  ```bash
  pip install suricata-update
  suricata-update update-sources
  suricata-update enable-source et/open
  suricata-update
  ```
- [ ] Enable only the relevant categories: `exploit`, `malware`, `policy`, `scan`
- [ ] Measure the false positive rate for 1 week before enabling any blocking actions
- [ ] Automate the weekly rule update with cron

## D+90 - Operational maturity and automation

### Infrastructure as Code

- [ ] Convert all configurations into Ansible roles:
  - `role/nftables`: rule deployment and management
  - `role/nginx_tls`: nginx configuration + certificates
  - `role/suricata`: installation, rules, IDS/IPS mode
  - `role/strongswan`: IPsec PKI tunnel
  - `role/sshd_hardening`: sshd configuration + keys
- [ ] Version the infrastructure in a Git repository with `dev`, `staging`, `prod` branches
- [ ] Implement a CI/CD pipeline (GitHub Actions or GitLab CI):
  1. Config validation (nginx -t, nft -c, suricata -T)
  2. Automated R1-R4 regression tests on an ephemeral VM
  3. Production deployment after validation

### Continuous security review

- [ ] Schedule a quarterly review of `Risk_Register.md`
- [ ] Subscribe to CVE alerts for the components in use (nginx, strongSwan, Suricata, OpenSSL)
  - CVE RSS feed: https://nvd.nist.gov/feeds/json/cve/1.1/nvdcve-1.1-recent.json.gz
  - Debian Security alerts: https://www.debian.org/security/
- [ ] Run a yearly vulnerability scan (OpenVAS, Nessus, or a full testssl.sh run)
- [ ] Document an operational runbook for each component:
  - Start/stop procedure
  - Configuration rollback procedure
  - Incident response procedure (critical Suricata alert)

### Extended regression tests

- [ ] Add an R5 test: full TLS configuration check with testssl.sh
- [ ] Add an R6 test: check that normal traffic does not generate an IDS alert (negative test)
- [ ] Integrate the tests into the CI/CD pipeline
- [ ] Generate a monthly compliance report (status of the 4 security controls)
